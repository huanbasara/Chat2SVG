\section{Stage 1: Template Generation}

\begin{bodytext}
This stage handles the initial conversion from text prompt to basic SVG structure.
\end{bodytext}

\subsection{Expand Text Prompt}

\begin{bodytext}
This step uses a predefined prompt template to expand the original short text prompt into a more detailed description. The process involves:
\end{bodytext}

\begin{bodytext}
\textbf{Process Flow:}
\begin{itemize}
\item Load the expand\_text\_prompt template from prompts.yaml
\item Replace the \textcolor{red}{\textbf{<TEXT\_PROMPT>}} placeholder with the actual user input
\item Send the complete prompt to the Large Language Model (LLM)
\item Receive expanded text prompt with detailed scene description, object breakdown, and layout information
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Implementation:} The code loads the template, performs string replacement, and sends the formatted prompt to the AI session for processing. The expanded result includes detailed object descriptions and component breakdowns that will be used in the next step.
\end{bodytext}

\subsection{Generate SVG Code}

\begin{bodytext}
This step generates SVG code based on the expanded text prompt from the previous step. The process involves:
\end{bodytext}

\begin{bodytext}
\textbf{Process Flow:}
\begin{itemize}
\item Load the write\_svg\_code template from prompts.yaml
\item Maintain session history including the previous expand text prompt request and response
\item Send the complete request (template + historical chat records) to the Large Language Model (LLM)
\item Receive SVG code that corresponds to the expanded text prompt
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Implementation:} The system maintains a session object that tracks the conversation history. When generating SVG code, it combines the write\_svg\_code prompt template with the accumulated chat history (including the expanded prompt from step 1.1) to provide the LLM with complete context for generating accurate SVG output.
\end{bodytext}

\subsection{Iterate Improvement}

\begin{bodytext}
This step refines the generated SVG code through iterative improvement using visual feedback. The process involves:
\end{bodytext}

\begin{bodytext}
\textbf{Process Flow:}
\begin{itemize}
\item Convert the generated SVG code to PNG image for visual analysis
\item Load the svg\_refine template from prompts.yaml
\item Send multimodal input to the AI: PNG image + svg\_refine prompt
\item Include historical request and response records from the session (which contains the SVG code from previous iterations)
\item Receive refined SVG code that corrects visual oddities and inconsistencies
\item Repeat for multiple iterations (cfg.refine\_iter) to progressively improve quality
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Implementation:} The system uses a multimodal AI model that can process both text (svg\_refine prompt) and images (rendered PNG). The SVG code from previous iterations is maintained in the session's historical records, allowing the AI to understand the current state while analyzing the visual rendering. By examining the PNG image, the AI can identify issues like misalignments, hidden elements, disproportionate scaling, and incorrect layering that may not be apparent from examining code alone. Each iteration builds upon the previous improvements while maintaining session context.
\end{bodytext}

\subsection{Best SVG Selection}

\begin{bodytext}
After iterative improvement, the system selects the best SVG from multiple candidates using evaluation models:
\end{bodytext}

\begin{bodytext}
\textbf{Evaluation Models:}
\begin{itemize}
\item \textbf{ImageReward}: Third-party reward model from THUDM (Tsinghua University), trained on 137k expert comparisons for text-to-image evaluation
\item \textbf{CLIP}: OpenAI's Contrastive Language-Image Pre-training model for multimodal understanding
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Selection Process:}
\begin{itemize}
\item Convert all candidate SVG files to PNG images for evaluation
\item Input text prompt + PNG images to the selected evaluation model
\item \textbf{ImageReward Output}: Ranking list based on human preference alignment
\item \textbf{CLIP Output}: Similarity scores between text and image features
\item Select the highest-scoring SVG as the final template output
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Model Characteristics:} Both models are general-purpose evaluation tools, not specific to SVG generation. ImageReward focuses on human preference-based quality assessment, while CLIP evaluates semantic text-image alignment. They use PNG format because these models are designed for raster image evaluation, providing reliable assessment of visual-textual correspondence.
\end{bodytext}

\section{Stage 2: Detail Enhancement}

\begin{bodytext}
This stage enhances the basic SVG output from Stage 1 by processing it through AI models to add details, improve visual quality, and apply artistic styles.
\end{bodytext}

\subsection{SVG Processing}

\begin{bodytext}
This step performs rule-based cleaning and normalization of the SVG template selected from Stage 1. The process standardizes the SVG format to prepare it for subsequent AI processing.
\end{bodytext}

\begin{bodytext}
\textbf{Input and Output:}
\begin{itemize}
\item \textbf{Input}: svg\_template\_path - Best SVG template selected by ImageReward/CLIP from Stage 1
\item \textbf{Output}: svg\_cleaned\_path - Cleaned and standardized SVG file ready for enhancement
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Two-Phase Cleaning Process:} The SVG cleaning employs two complementary tools to achieve comprehensive standardization:
\end{bodytext}

\begin{bodytext}
\textbf{Phase 1: picosvg Standardization}

\textcolor{green!40!black}{\textbf{Tool Overview:}} picosvg is a command-line tool developed by Google Fonts team, specifically designed to simplify SVG files for font build processes. It transforms complex SVG structures into standardized "pico" (minimal) format containing only essential rendering elements.

\textcolor{green!40!black}{\textbf{Implementation:}} The system executes picosvg as an external command-line process using \texttt{os.system()}, redirecting output to the cleaned SVG file:
\begin{verbatim}
os.system(f'picosvg {svg_template_path} > {svg_cleaned_path}')
\end{verbatim}

\textcolor{green!40!black}{\textbf{Key Standardization Functions:}}
\begin{itemize}
\item \textbf{Coordinate Normalization}: Converts all coordinates to absolute values, eliminating relative positioning
\item \textbf{Command Expansion}: Removes SVG path shorthand (H, S, etc.), using only full coordinate commands
\item \textbf{Structure Simplification}: Ensures exactly one \texttt{<defs>} element as first child, followed only by \texttt{<g>} and \texttt{<path>} elements
\item \textbf{Metadata Removal}: Strips editor-specific attributes and unnecessary XML elements
\item \textbf{Format Consistency}: Produces deterministic output format suitable for machine processing
\end{itemize}

\textcolor{green!40!black}{\textbf{Why picosvg for AI-Generated SVG:}} AI-generated SVG files often contain inconsistent formatting, relative coordinates, and complex structures that can interfere with downstream processing. picosvg standardizes these variations into a predictable format that the subsequent svglib processing can reliably handle.
\end{bodytext}

\begin{bodytext}
\textbf{Phase 2: svglib Optimization}
\begin{itemize}
\item \textbf{Path Conversion}: Convert all elements to standardized paths (to\_path)
\item \textbf{Arc Simplification}: Simplify complex arc representations (simplify\_arcs)
\item \textbf{Visibility Optimization}: Remove completely obscured paths (remove\_invisible\_paths)
\item \textbf{Bezier Standardization}: Convert lines to Bezier curves and split complex paths (line\_to\_bezier, split\_paths)
\item \textbf{Redundancy Removal}: Filter duplicates, consecutive elements, and empty paths (drop\_z, filter\_duplicates, filter\_consecutives, filter\_empty)
\item \textbf{Precision Control}: Save with 6-digit coordinate precision for optimal quality
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Purpose of Rule-Based Cleaning:}
\begin{itemize}
\item \textbf{Format Normalization}: Standardize AI-generated SVG to consistent, predictable format
\item \textbf{Noise Reduction}: Remove redundant elements that could interfere with diffusion models
\item \textbf{Processing Preparation}: Ensure compatibility with downstream image diffusion and SAM processing
\item \textbf{Performance Optimization}: Reduce file size and computational complexity for subsequent stages
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Deterministic vs. Creative Processing:} Unlike the creative AI processes in other stages, this step applies deterministic, rule-based transformations that produce consistent results. It serves as a crucial bridge between the creative SVG generation in Stage 1 and the creative enhancement in Stage 2b, ensuring data quality and format consistency.
\end{bodytext}

\subsection{Image Diffusion}

\begin{bodytext}
This step uses a Diffusion Pipeline to generate 4 enhanced images from the cleaned SVG, combining img2img content generation with ControlNet structure preservation.
\end{bodytext}

\begin{bodytext}
\textbf{Pipeline Architecture: StableDiffusionXLControlNetImg2ImgPipeline}
\begin{itemize}
\item \textbf{Framework}: Hugging Face Diffusers standard pipeline
\item \textbf{Type}: SDXL + ControlNet + img2img combined architecture
\item \textbf{Dual Input}: Original SVG image (content) + Blurred SVG image (structure control)
\item \textbf{Output}: 4 enhanced PNG images per generation
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Model Components:}
\begin{itemize}
\item \textbf{Main Model}: aamXLAnimeMix v1.0 - SDXL-based anime-style model (6.46GB, Civitai)
\item \textbf{ControlNet}: controlnet-tile-sdxl-1.0 - Structure preservation model (Hugging Face)
\item \textbf{Compatibility}: Both models use SDXL architecture family for seamless integration
\end{itemize}
\end{bodytext}

\subsection{SAM Processing}

\begin{bodytext}
This step extracts new detail regions from the enhanced image and converts them to SVG paths, using a two-stage comparison approach with the Segment Anything Model.
\end{bodytext}

\begin{bodytext}
\textbf{Two-Stage Segmentation Strategy:}
\begin{itemize}
\item \textbf{Stage 1 - Original Image}: Segment cleaned SVG rendering using coarse configuration (24×24 grid points)
\item \textbf{Stage 2 - Enhanced Image}: Segment Diffusion-enhanced PNG using fine configuration (48×48 grid points)
\item \textbf{Rationale}: Enhanced images contain more details, requiring denser sampling for complete capture
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{SAM Model Configuration:}
\begin{itemize}
\item \textbf{Architecture}: Vision Transformer (ViT-Huge, 630M parameters)
\item \textbf{Working Mode}: Grid-point automatic segmentation (no manual prompts)
\item \textbf{Coarse Config}: 576 sampling points, min area 100px (capture main regions)
\item \textbf{Fine Config}: 2304 sampling points, min area 30px (capture fine details)
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Mask Comparison and Selection:}
\begin{itemize}
\item Compare enhanced image masks against original image masks
\item Filter new masks by: size constraints, overlap threshold (IoU < 0.4), visibility ratio
\item Select only genuinely new regions added by Diffusion enhancement
\item Reject duplicates, noise fragments, and heavily occluded areas
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Vectorization Process:}
\begin{itemize}
\item Extract contours from selected binary masks using edge detection
\item Simplify contours to polygons with optimized point reduction
\item Extract dominant colors from corresponding image regions
\item Convert to SVG path format: MoveTo (M) → LineTo (L) → ClosePath (Z)
\item Add new paths to original cleaned SVG while preserving existing elements
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Final Output:} Enhanced SVG containing original paths plus new detail paths extracted from Diffusion-generated enhancements, combining the structure preservation of the original design with artistic details from AI enhancement.
\end{bodytext}

\section{Stage 3: SVG Optimization}

\begin{bodytext}
This stage refines the enhanced SVG from Stage 2 using a specialized VAE model to optimize path geometry, improve aesthetic quality, and ensure visual coherence. The process involves three sequential phases: parameter initialization, latent inversion, and latent optimization.
\end{bodytext}

\subsection{Parameter Initialization}

\begin{bodytext}
The Painter class serves as the central container for all optimization parameters and functionality. It manages SVG paths, trainable parameters, rendering operations, and result saving in a unified interface.
\end{bodytext}

\begin{bodytext}
\textbf{Painter Initialization:}
\begin{itemize}
\item Load cleaned SVG file and target PNG image from Stage 2
\item Parse SVG paths into manageable shape objects and control points
\item Set up rendering canvas with standardized dimensions (512×512)
\item Initialize device configuration for GPU/CPU computation
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Parameter Categories:} Four types of trainable parameters are initialized for each SVG path:
\begin{itemize}
\item \textbf{Latent Vectors}: 24-dimensional vectors controlling geometric aesthetics (core parameters)
\item \textbf{Affine Transforms}: Rotation angles, scale factors, translation coordinates
\item \textbf{Visual Properties}: Fill colors, stroke colors, stroke widths
\item \textbf{Regularization}: Background parameters and rendering settings
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Latent Vector Initialization:} Instead of random initialization, the system uses circle.svg from the VAE dataset. This reference SVG is encoded through the VAE to generate a meaningful 24-dimensional starting vector, which is then cloned for each path in the target SVG.
\end{bodytext}

\subsection{Latent Inversion}

\begin{bodytext}
Latent Inversion performs "reverse engineering" to find optimal 24-dimensional vectors that, when decoded by the VAE, produce paths closely matching the original SVG geometry.
\end{bodytext}

\begin{bodytext}
\textbf{Process Overview:}
\begin{itemize}
\item \textbf{Starting Point}: Each path begins with circle.svg's encoded vector (aesthetically valid but geometrically incorrect)
\item \textbf{Target Preparation}: Original SVG paths are sampled into dense point sets as matching targets
\item \textbf{Iterative Adjustment}: VAE decoder generates paths from current vectors, compared against targets
\item \textbf{Individual Optimization}: Each path optimizes independently toward its specific target shape
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Why "Inversion"?} The process reverses normal VAE flow:
\begin{itemize}
\item \textbf{Normal VAE}: Original SVG → Encoder → Latent Vector → Decoder → Reconstructed SVG
\item \textbf{Latent Inversion}: \textcolor{red}{? Latent Vector} ← Optimization ← Decoder → Compare with Target
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Loss Function Structure:} The optimization focuses on single-path accuracy without considering inter-path coordination:
\begin{itemize}
\item \textbf{Shape Matching}: EMD loss comparing decoded paths with target point sets
\item \textbf{Smoothness}: Laplacian smoothing loss ensuring path continuity
\item \textbf{Regularization}: KL divergence maintaining vectors within valid VAE distribution
\item \textbf{No Coordination}: No MSE, IoU, or inter-path relationship constraints
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Output}: Each path obtains its optimized 24-dimensional "identity vector" that produces the desired shape when decoded, serving as the foundation for the subsequent coordination phase.
\end{bodytext}

\subsection{Latent Optimization}

\begin{bodytext}
Latent Optimization shifts from individual path accuracy to global image coordination, ensuring the overall rendered result matches the target image from Stage 2's diffusion output while maintaining path shape integrity.
\end{bodytext}

\begin{bodytext}
\textbf{Optimization Target Shift:}
\begin{itemize}
\item \textbf{Input}: Optimized latent vectors from Latent Inversion (individually accurate)
\item \textbf{Goal}: Coordinate all paths to collectively render an image matching the diffusion target
\item \textbf{Global Perspective}: Focus on overall visual coherence rather than individual path precision
\item \textbf{Dual Constraints}: Balance target image similarity with original path shape preservation
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Core Optimization Loop:} The process iteratively adjusts latent vectors through a comprehensive loss function:
\begin{itemize}
\item \textbf{Decode}: VAE decoder converts current latent vectors to SVG control points
\item \textbf{Transform}: Apply affine transformations (rotation, scale, translation) to each path
\item \textbf{Render}: Generate complete image from all transformed paths combined
\item \textbf{Compare}: Calculate multiple loss terms against various targets (image, shape, distribution)
\item \textbf{Update}: Backpropagate gradients to adjust latent vectors and transform parameters
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Multi-Objective Loss Structure:} Unlike single-path focus in Latent Inversion, this stage balances five different optimization objectives simultaneously, each targeting different aspects of visual quality and structural integrity.
\end{bodytext}

\begin{bodytext}
\textbf{Gradient-Based Parameter Updates:} The optimization uses standard PyTorch autograd to adjust trainable parameters:
\begin{itemize}
\item \textbf{Primary Targets}: 24-dimensional latent vectors (core geometric control)
\item \textbf{Secondary Parameters}: Affine transform coefficients, colors, stroke properties
\item \textbf{Fixed Elements}: Pre-trained VAE model weights remain frozen throughout
\item \textbf{Update Process}: Adam optimizer with cosine learning rate scheduling
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Output}: SVG with globally coordinated paths that collectively produce visually coherent results matching the target image while preserving individual path semantic integrity.
\end{bodytext}

\subsection{Point Optimization}

\begin{bodytext}
Point Optimization abandons latent space constraints and directly optimizes SVG control point coordinates for pixel-level precision.
\end{bodytext}

\begin{bodytext}
\textbf{Core Changes:}
\begin{itemize}
\item \textbf{Optimization Target}: Latent vectors → Direct control point coordinates
\item \textbf{Computation Path}: Control points → Render → Image → Loss (bypasses VAE)
\item \textbf{Coordinate System}: 256×256 → 512×512 (pure mathematical scaling, zero distortion)
\item \textbf{Differentiable Rendering}: Uses pydiffvg for geometry-to-pixel gradient flow
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Loss Functions}: Only essential components
\begin{itemize}
\item \textbf{MSE Loss}: Pixel-level matching with target image
\item \textbf{Curvature Loss}: Geometric smoothness (weight decays from 2.0 to 0.1)
\item \textbf{Removed Constraints}: No KL divergence (no latent space), no IoU loss
\end{itemize}
\end{bodytext}

\begin{bodytext}
\textbf{Technical Advantage}: Breaks VAE limitations through direct coordinate optimization for maximum precision geometric control.
\end{bodytext}
